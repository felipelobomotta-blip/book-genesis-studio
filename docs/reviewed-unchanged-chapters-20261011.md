# Retaining already-correct chapters in factual groups

A full-book proofreading ticket can legitimately cover every chapter even when
only some chapters need an edit. In the two frozen native runs on October 11,
such groups covered spelling consistency and dialogue punctuation. The old
per-chapter correction validator required every group member to change. An
already-correct member could therefore reject the entire group, including its
valid corrections.

Grouped factual proposals now allow an empty correction list. This retains the
original bytes and still sends the member, every proposed companion, the full
original manuscript, and the existing canon to a fresh correctness reviewer.
The reviewer must block a member that falsely claims its defect is already
resolved. Single-chapter corrections and creative revisions keep their existing
substantive-change requirement.

Version 2 factual manifests distinguish actual publications from reviewed
unchanged members. Only changed chapters are published or counted as revisions.
A wholly unchanged group requires review but creates no promotion receipt. The
transaction verifies the complete reviewed manuscript before publishing, so a
concurrent change to a retained chapter also invalidates the decision. Version
1 evidence remains verifiable without changing its original review packet.

Regression coverage includes mixed and wholly unchanged groups, false retention
claims, interrupted publication, retained-member tampering, Markdown and EPUB
delivery, and completed resume without extra model calls. These are synthetic
transport checks. They establish the code contract; they do not establish
literary quality or successful native delivery. Existing native books continue
under their original frozen source versions.

The complete Windows suite passed 449 tests in 748.432 seconds, and the skill
installer's `verify-suite` check passed. Native validation of this new behavior
remains outstanding at this source checkpoint.
