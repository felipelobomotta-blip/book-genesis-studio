# Book Genesis: competitor strengths and engine lessons

Research date: 2026-10-25. Scope: all 16 products/apps and 13 repositories/catalogs in the preceding [landscape](../competitive-landscape-20261025.md). The catalog is evaluated as a discovery/evaluation resource; its 200+ entries were not individually audited. This study identifies the strongest visible mechanism in each product, rather than declaring measured winners.

## Method and evidence

- Public SaaS/app websites and official documentation establish advertised behavior. They do not expose their private orchestration or demonstrate consistent output quality.
- For all 13 open projects, repository READMEs and tree snapshots were retrieved. Eighteen additional implementation, skill, architecture, schema, and evaluation files were inspected selectively at pinned commits. The [source manifest](competitive-study-20261025-evidence.json) records Git commit and blob identities; it is not a claim that every source file was read.
- Evidence labels below: **P** = public product description or sample presentation; **D** = documented workflow/technical contract; **C** = static implementation inspected. None means a competitor was run or benchmarked.
- No signup, purchase, third-party inference, installation, proprietary source access, or comparative full-book test was performed. “Best” means my assessment of the most useful observed design choice, not a literary-quality ranking.

## Open projects: useful methods and their tradeoffs

| Project | Strongest observed mechanism | Evidence / limitation | Application to Book Genesis |
|---|---|---|---|
| [Story Skills](https://github.com/danjdewhurst/story-skills) | Explicit chronology and state make some consistency checks deterministic; the pacing module tracks scene outcomes, reaction scenes and chapter hooks as advisory signals. | C: `src/deaths.js`, `src/pacing.js`. The checker reads declared metadata; incorrect or missing declarations can hide a prose problem. Its warnings are not literary grades. | Extend the existing ledger with source-linked state transitions; flag repetitive scene patterns without forcing all genres into one beat formula. |
| [Quill](https://github.com/gc4rella/quill) | A small chapter handoff combines summaries, open threads, active entities and a verbatim ending excerpt; revisions flag downstream impact. | D: `SKILL.md`, workflow references. A fixed 1,500-token brief and three-nearby-chapter window are deliberate limits, not proven lossless compression. | Use layered, budgeted context with targeted retrieval for distant dependencies; retain voice with a short actual prose handoff. |
| [Novel Writing](https://github.com/guantoubaozi/novel-writing) | Confirmed facts, inferences and future plans are distinct. Update packets are validated and merged into a copy before atomic writing; an expected SHA can bind an approved packet. | C: `scripts/merge_story_updates.py`. The viewed merge code validates packet/data integrity; explicit author-curation policy lives in the workflow. | Keep speculative plans out of character knowledge; derive state changes only from accepted prose. Reuse the principle, not an extra parallel state engine. |
| [Claude Book Skill](https://github.com/luquiluke/claude-book-skill) | A voice profile records sample provenance, writing register, measured habits and confidence; book-register samples outrank casual posts. | D: `references/style-analysis.md`. It specifies how to sample and calibrate; no performance test was executed. | Offer an optional personal corpus and a calibrated sample. A novice with no corpus still needs a low-confidence starting profile. |
| [Calliope writing-skills](https://github.com/Calliope-Editor/writing-skills) | Its line editor diagnoses recurring craft patterns using a quote, named issue, principle and repair direction. It keeps critique separate from drafting. | D: line-editor skill. The augmentation-only prohibition on writing is intentional and does not match our autonomous product contract. | Keep an independent diagnosis stage, then route accepted, evidenced findings to a different writer role. |
| [Oh Story DSH](https://github.com/zenstory-ai/oh-story-dsh) | The host owns sessions, credentials, models, approvals and the agent loop; the plugin contributes creative files, skills, roles and the workbench. Files remain the creative source of truth. | D: `docs/ARCHITECTURE.md`. It describes pinned upstream packs and host versions. Integration was not run here. | Strengthen native plugin integration and a file-backed progress view; avoid introducing a second competing agent runtime. |
| [NovelNovel](https://github.com/wanrenhuifu/NovelNovel) | Its lore-filter API asks the model which known candidates to **drop**, not which arbitrary entries to invent or keep. Invalid/unavailable filtering falls back to the recalled candidates. | C: `src/domain/loreFilter.ts`. Recall quality still bounds what the filter can preserve. | Use constrained IDs and safe defaults in context selection. Critical facts should have mandatory inclusion independent of a model's relevance vote. |
| [dsh-tool-writing](https://github.com/x2802490130-prog/dsh-tool-writing) | Dynamic world state separates current object locations and terms from static setting cards; the local search module supports retrieval. | C: `lib/worldstate.js`, `lib/search.js`. State rendering uses recency caps and object history is capped at 40; bigram search is lexical, not proof of semantic recall. | Keep dynamic custody/state, but preserve old unresolved clues and hard constraints outside recency caps. |
| [Long Novel Agent Kit](https://github.com/mushroomfk/long-novel-agent-kit) | Explicit handoff/session fingerprints, proposal schemas and an MCP read-only launch mode help prevent stale state changes across agents. | C/D: proposal schema, server tool definitions and README. Read-only mode is a launch option; the inspected server initializes its mode flag false. Its very large CLI is a maintainability tradeoff, not a design to copy wholesale. | Reuse existing Book Genesis hashes/resume receipts; add small missing preconditions rather than importing another full memory system. |
| [Snowflake Novel Writer](https://github.com/renky1025/agent-skills/tree/main/snowflake-novel-writer) | Progressive expansion connects premise, structure, thematic counterargument, character contradictions, relationship secrets, scenes and a voice sample. | D: `references/snowflake-steps.md`. It is a method contract with genre/style assumptions; no full-book reliability was established. | Challenge and improve the plan before expensive prose generation; offer structure choices based on the author's intention. |
| [Awesome Novel Skills](https://github.com/UnderleveledBuilder/awesome-novel-skills) | Taxonomy and linked comparative evaluations separate repository curation from testing. The topic-selection comparison includes a no-skill baseline and repeated runs. | D: README and `evals/README.md`. Linked tests cover topic selection and AI judges, not book quality, sales or all catalog entries. Raw runners/results were not audited here. | Use it to discover candidates and borrow the baseline/repeated-trial evaluation design, while preserving the limits of AI judging. |
| [Book-writing-skill](https://github.com/swiftugandan/book-writing-skill) | A physical production gate measures rendered geometry, clipping, page counts, folio consistency and CSS/diagram problems. | C: `bookkit/verify.py`. Static source inspection confirms the checks exist, not that they passed on a book we generated. | Extend export acceptance to rendered-page legibility/overflow as well as EPUB structure; separate prose acceptance from production acceptance. |
| [Yunn novel-writer](https://github.com/Yunshiro/yunn-skills) | Arc-level checkpoints and precise per-chapter state updates make continuation explicit; mechanical prose metrics are implemented in a helper. | C/D: continuity reference and `check_novel.py`. Several thresholds count Chinese characters/paragraph patterns and should not be transplanted into English literary evaluation. | Track hook variety, unfinished actions and arc-level changes, using genre/language-appropriate signals rather than rigid universal ratios. |

## What to adopt first, based on the Book Genesis trial

The beta 6 run produced 24 chapters / 83,517 prose words and a manuscript/EPUB, but its final automated literary result was 72.52/100 with a 6.5/10 floor. Pacing, prose and market positioning remained weak. Earlier baseline evidence, failed attempts and the installed frozen plugin must remain intact. These are proposed improvements, not implemented results of this research.

1. **Fix evidence handling before spending more on broad rewrites.** Reviewers should select validated passage IDs; the engine should render the corresponding text from canonical bytes rather than asking a model to reproduce long quotations perfectly. A selected passage still needs a separate support check: a valid location alone does not prove a finding. Repeated IDs/unknown sources must remain errors. Target `workflow_issues.py`, correction/group review validators and their schemas. The earlier issue-ID fix is a partial improvement, not a solution to every quote-support failure.
2. **Improve the plan and the first voice sample before writing 80k words.** Connect each scene's goal, resistance, change, cost and consequence to the next; review repetitive scene mechanisms and prolonged deferrals. Calibrate a representative prose sample against the brief. Use Story Skills' advisory pacing signals, Sudowrite's scene-first contract and Snowflake's progressive expansion. Do not force a reversal every fixed percentage across all genres.
3. **Make revisions bounded by actual dependencies.** The trial's creative revision groups spanned the whole book and suffered evidence failures. Repair a coherent local scene/arc when possible, include all chapters required by a real causal dependency, then validate that change before expanding the next task. Never split dependent corrections merely to bypass a group gate. Target `autonomous_book.py`, `revision_plan_context.py`, `revision_context.py`, `creative_groups.py` and `correction_groups.py`.
4. **Strengthen existing continuity rather than adding another memory stack.** Book Genesis already stores chapter continuity deltas and review evidence. Extend this with typed facts, custody transitions, knowledge recipients, story time, reader disclosure and source passage IDs, with planned/inferred facts kept distinct. Any retrieval policy must always include the hard constraints for the current scene.
5. **Give prose its own focused pass after structure works.** Use the author/character voice profile, flag repeated mechanisms and interpretive closing paragraphs, then compare original and candidate blindly. Avoid token substitution, punctuation bans or classifier-based “humanity” scores as a definition of literary quality. Calliope's diagnosis pattern and Claude Book Skill's corpus confidence are useful references.
6. **Expose existing proof in a simple progress surface.** Show writing/review/export state, elapsed time, chapter progress, visible generated prose and the next concrete action. A saved artifact, editorial acceptance and export readiness need distinct labels. Author Magic, Sopher, Novelyn and Oh Story DSH are useful presentation references. Display observable operations, not fabricated private model thinking.
7. **Use different engines for fiction and evidence-based nonfiction.** Fiction needs scene/character knowledge and payoff logic; nonfiction needs claims, actual sources, reader prerequisites and citations. BookBud's source-before-draft design and Inkloom's per-book-type memory are useful references. A failed factual lookup must not become an invented citation.
8. **Evaluate improvements with a frozen comparison.** Use the same model and effort (Codex gpt-5.6-luna/high for the authorized book trials), identical briefs, preserved before/after versions, blinded order, a no-new-method baseline and repeated cases. Report delivery success and unresolved findings separately from automated reader judgments. Reserve claims about human literary quality for human reading evidence; sales/bestseller potential require separate commercial evidence.

## Practical priority

The most relevant references for the current literary gap are **Sudowrite/Snowflake/Story Skills** for scene and structure, **Claude Book Skill/Calliope** for prose diagnosis, and **Novelcrafter/Novel Writing** for time-aware facts. **Author Magic/Oh Story DSH** are the strongest presentation/host-integration references in this study. These selections are an implementation judgment, not market-share or quality rankings.

A small next milestone should prove: one recurring mid-book defect repaired in a frozen excerpt/arc; valid evidence throughout; a blinded preference for the candidate; and no new continuity errors. That isolates the engine's current weakness before funding another entire manuscript. Full autonomous complete-book validation still follows after the fixes.
