# Three rubric readings per complete-manuscript assessment

The frozen validation protocol for trial 40 specified three independent raw
rubric readings, while that source's autonomous runner actually requested two.
The discrepancy was found before trial 40's first whole-book literary score.
Its original source, protocol, book, model responses and eventual verdict remain
unchanged; it is not evidence that the three-reading protocol was satisfied.

This candidate reserves three distinct native rubric steps for each current
manuscript assessment. All reports are retained, including a strict third
reading or an unassessed dimension. Each step has its own response and original
validation; identical input packets do not reuse another replica's judgment.
Replay of an already completed step keeps that same original receipt.

Aggregation still takes the median of each dimension, then subtracts the same
0.8 same-family calibration. The weights, strict weighted target, dimension
floor, reader panels, historical issues, audits and revision budgets are
unchanged. Disagreement of at least 1.5 points still lowers confidence, and an
unassessed dimension in any reading still prevents a complete passing score.
Writers and critics receive the same allowed evidence as before; neither
receives a desired score or an earlier critic's number.

The added tests check a strict outlier, genuine three-value medians, exact 90
remaining insufficient, an unassessed third reading, packet privacy and
replaying all three receipts without new calls. Synthetic test scores are
execution fixtures, never literary acceptance evidence. Fresh native
complete-book validation of this candidate remains required.

## Windows recovery discovered in trial 40

The preserved 24-chapter, 84,548-word draft stopped at its final drafting
continuity call. The native call timed out, external tree shutdown could not
be verified, and the next attempt encountered the retained active lock.
No whole-book assessment or export completed. The failed trial stays unchanged.

The native guard now uses the same private kill-on-close Windows job already
used by the launcher. The helper ships inside the installed skill and the
launcher imports that one implementation. A child starts suspended, joins its
job, then runs. Timeout, interruption, normal parent exit and post-launch errors
must drain that owned job before response publication or lock release. A failure
to verify shutdown still retains ownership. Each receipt records the actual
process boundary and shutdown result. Loading the guard by file path does not
depend on the caller's Python import path.

Real local process tests reproduced surviving descendants on the frozen source,
then checked timeout and a fresh retry, an orphaned descendant, a metadata
failure after parent exit, unrelated-process preservation and isolated imports.
These controls do not generate or grade a book.

## Temporary installation sharing failures

Integration testing also reproduced Windows access denial when promoting a
staged skill directory. Installation now retries only Windows access/sharing
errors for at most 1.55 seconds, retaining the same staged content. An unexpected
new destination or replaced staged directory stops promotion. Rollback removes
only a target actually promoted by this transaction; an external target and the
original backup remain available instead of being deleted. Persistent locks and
unrelated filesystem errors still fail and restore the prior installation where
the destination remains available. Tests exercise actual Windows directory
handles, not just fabricated successful rename responses.

The three-reading correction and these execution repairs leave the writing
prompts, saved manuscripts, literary targets and original unfavorable reports
unchanged. Full regression and native transport results are reported separately
from complete-book acceptance.
