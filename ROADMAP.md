# Recovery roadmap

The current checkout is **5.1.0-dev**, an unreleased recovery of the agent-native
writing workflow. Priorities follow observed book-generation failures. A high
test count is not a completed product or a literary-quality rating.

## Complete the author journey

- [x] Keep one writing skill and a small launcher that uses the selected native CLI.
- [x] Prepare and test the headless Codex role command without reconstructing interactive flags.
- [x] Bind reader and rubric evidence to complete, frozen manuscript paragraphs.
- [x] Verify factual corrections separately from creative preference, without fabricated votes.
- [x] Count anonymous comparisons from their original mapping and validated responses.
- [x] Preserve Unicode review receipts through Windows shell pipelines.
- [ ] Persist revision counters and checkpoint state before beginning another pass; an interrupted run must not regain its spent budget.
- [ ] Demonstrate that the native orchestrator executes the independent plan check and every required phase, including the five-chapter continuity check.
- [ ] Close a fresh idea-to-export run on the exact current checkout without editorial rescue or silent changes to the skill snapshot.
- [ ] Repeat with a full-length manuscript inside its declared production contract.

## Establish quality and usability

- [ ] Show that a complete-book audit catches contradictory document custody, character roles and causal dependencies, and that accepted repairs actually close those findings.
- [ ] Keep current-draft reader, rubric, audit and export evidence bound to the final canonical text.
- [ ] Record unresolved literary gates honestly in the delivered book package.
- [ ] Measure elapsed time, completed and failed native calls, retries and available usage evidence; do not infer price from a subscription name.
- [ ] Observe an independent beginner installing, starting, recovering and opening the delivered book without maintainer repair.
- [ ] Obtain independent human feedback on the complete manuscript. Simulated readers remain labeled as simulated.

## Release and compatibility

- [ ] Meet the [release checklist](RELEASE_CHECKLIST.md) and publish a reproducible acceptance report.
- [ ] Verify Windows, Linux and macOS checks and runtime-specific claims separately.
- [ ] Run complete-book acceptance in each host advertised as fully supported; distinguish skill installation from generation proof.
- [ ] Record the exact resolved host and model for Claude Code and other providers. An alias or substitute model is not the requested model's validation.
- [ ] Publish the walkthrough and update the landing page only around behavior the released commit demonstrates.

No sales, bestseller or 90/100 claim is established by these checkboxes. A
numerical product rating needs a disclosed evaluation method and evidence;
unresolved failures in the central author journey prevent a readiness claim.
